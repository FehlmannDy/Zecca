# Decisions

Choices made during the build that the brief left open, and the result of every "to verify" item. Newest last.

| # | Date (UTC) | Decision | Why / evidence |
|---|---|---|---|
| 1 | 2026-11-20 19:45 | Lint is `tsc --noEmit` over every package (strict). No ESLint. | Lightest option (BUILD §4); typecheck catches what matters here. |
| 2 | 2026-11-20 19:50 | Packages are consumed as TypeScript source (`main: src/index.ts`). Services run with `tsx`; Next.js uses `transpilePackages`. | No build step between packages; one Dockerfile runs `tsx`. |
| 3 | 2026-11-20 19:55 | Extra package `packages/ledger-mock`: the in-memory `Ledger` (LEDGER_MODE=mock), owned by the orchestrator. | Keeps the mock independent of `xrpl-core`, so wave 1 can start on it at once. |
| 4 | 2026-11-20 20:05 | **Auth (SPEC §6.1): Privy access token.** The page reads it from the adapter's internal client (`adapter.session.client.getAccessToken()`, adapter pinned at 1.1.0-rc.0); the API verifies the ES256 JWT against `https://auth.privy.io/api/v1/apps/<appId>/jwks.json` (iss `privy.io`, aud = app id), then looks up the DID's XRPL wallet through the Privy API with the app secret and binds the session to that address. `SIGNER_MODE=mock` uses the fallback: `POST /v1/auth/nonce`, the client signs SHA-512Half(UTF-8 message) through the raw_sign contract, the API checks it with `ripple-keypairs.verify` and that the key derives the address. Fallback for Privy if the internal field breaks: nonce signed as a never-valid AccountSet through `manager.sign` (one extra approval). | Spike: the adapter exposes no public token API but its js-sdk-core client is reachable at runtime; `signMessage` throws (no message signing); JWKS is live. |
| 5 | 2026-11-20 20:05 | `manager.sign(tx)` leaves every field untouched when `Fee` and `Sequence` are present (it only sets `Account`/`SigningPubKey`, applies DER + low-S, verifies). So the sponsor policy compares the signing hash with `SigningPubKey` set to the user's key. The API always fills Fee, Sequence and LastLedgerSequence. Fee must stay ≤ 2 XRP (adapter refuses more). | Spike, adapter source `prepareSigningInput`. |
| 6 | 2026-11-20 20:05 | **Google login: built, behind `FEATURE_GOOGLE_LOGIN`.** The adapter offers it natively: `manager.connect('privy', { loginMethod: 'google' })`, and `/wallet/privy` calls `manager.reconnect()` with the same manager instance. Needs `http://localhost:3100/wallet/privy` in the Privy dashboard's allowed redirects (HUMAN_STEPS). | Spike, adapter source. Not run yet. |
| 7 | 2026-11-20 20:05 | **Face ID (passkey MFA): off (`FEATURE_PASSKEY=0`), copy never mentions it.** The adapter has no MFA handling; js-sdk-core emits `mfaRequired` on raw_sign and the adapter never answers it, so a sign would hang and fail; Privy documents MFA for EVM/Solana only. Revisit only if everything else is done. | Spike, adapter + js-sdk-core source. |
| 8 | 2026-11-20 20:10 | XRP amounts in the API are integer **drops** (`depositedDrops`, `valueDrops`, `amountDrops`) instead of SPEC's `depositedXrp`/`valueXrp`/`amountXrp`. | BUILD §8 rule 5: integers in minor units everywhere, no floats. |
| 9 | 2026-11-20 20:10 | Added to the API beyond SPEC §6: `POST /v1/auth/nonce`, `POST /v1/ramp/sign` (MoonPay SDK URL signing), `GET /v1/demo/shop/items`, `GET /v1/payment-requests/:id/events` is listed in the route table, `GET /v1/health`. `PublicConfig` carries modes, fees, limits, explorer URLs. `ApiError.error.details` carries the limit hit. Activity may carry a `receipt` and a `ciphertextPreview`. | Needed by the screens in UI.md; additive only. |
| 10 | 2026-11-20 20:10 | Key store roles beyond SPEC §4.2: `marketIssuer`, `oracle`, `demoShop`. Wallet secrets cross the interface as `{ address, seed, algorithm }`; `xrpl-core` turns them into `xrpl.Wallet`. Non-secret ledger ids (issuance ids) live in the key store's `meta`. | Market issuer and demo shop need keys (SPEC §4.9, §4.14); keeps `contracts` free of `xrpl`. |
